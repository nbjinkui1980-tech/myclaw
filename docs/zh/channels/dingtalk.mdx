description: "通过您所在组织的钉钉机器人与智能体交互"

---

将 IronClaw 连接到企业内部应用机器人，组织内的成员即可在单聊中，以及在群里 @机器人，与您的智能体对话。

IronClaw 使用 Stream 模式**主动向外**连接钉钉，不需要公网地址、隧道或 Webhook 地址。

<Warning>
**尚未在真实的钉钉组织中验证。** 网关主机名、权限点名称以及部分消息字段，是依据钉钉公开的 SDK 源码编写的，没有用真实连接确认过。本页写“以钉钉当前界面为准”的地方，以您在钉钉开放平台看到的界面为准。遇到问题时，请对照[常见问题](#常见问题)中的状态和原因码。
</Warning>

## 适用范围

- **一个 IronClaw 部署只对接一个钉钉组织。** 运营者自行托管 IronClaw，并使用在自己组织内创建的应用。不支持一个部署对接多个组织，也不支持发布到钉钉应用市场。
- **每组应用凭证只运行一个 IronClaw 实例。** 不要用同一组 ClientID 和 ClientSecret 同时启动第二个实例，或同时用于测试和生产环境。钉钉如何在同一应用的多个连接之间分发消息尚未确认，第二个实例可能抢走本应属于第一个实例的消息。
- 只有您组织的成员可以使用机器人。其他组织成员的消息（例如跨组织群）会被丢弃，且没有任何回复。

## 设置

<Steps>
<Step title="创建企业内部应用">
在钉钉开放平台中，于您的组织内创建企业内部应用，并为其添加**机器人**能力。菜单名称可能变化，请以钉钉当前界面为准。
</Step>
<Step title="将机器人设为 Stream 模式">
在机器人设置中，把消息接收模式选为 **Stream 模式**（不是 HTTP 回调），然后**发布**应用使其生效。具体名称以钉钉当前界面为准。
</Step>
<Step title="申请权限并设置可用范围">
申请应用发送机器人消息所需的接口权限，并设置应用的可用范围，使其包含将要与机器人对话的人。这里不列出权限点名称，因为尚未核实；请在控制台中找到用于机器人向单聊发送消息、以及向群聊发送消息的权限并申请，具体名称以钉钉当前界面为准。
</Step>
<Step title="复制 ClientID 和 ClientSecret">
在应用的凭证页面复制 **ClientID**（也称 AppKey）和 **ClientSecret**（也称 AppSecret）。

<Warning>
ClientSecret 等同于应用的完整凭据。请勿粘贴到聊天、代码仓库、工单或截图中。
</Warning>
</Step>
<Step title="启动 IronClaw 并填写凭证（运维人员，每个实例一次）">
```bash
ironclaw serve
```

在 [Web 界面](/using/webui)中打开 **Admin → Configuration**，找到 **DingTalk deployment configuration** 卡片，填写 ClientID 和 ClientSecret 并保存。两个值都保存在加密的密钥存储中，保存后不会再次显示。每个值只需填写一次。
</Step>
<Step title="安装扩展">
打开 **Extensions**，找到 **DingTalk** 并安装。激活扩展后，IronClaw 会连接钉钉。
</Step>
<Step title="把机器人加入测试群（可选）">
要在群里使用，请先在钉钉中把机器人加入该群。群里只有 @机器人 的消息才会得到回复。
</Step>
</Steps>

## 确认已经连上

**Extensions** 页面中的 DingTalk 卡片会显示连接状态。

| 状态 | 含义 | 处理办法 |
| --- | --- | --- |
| **Connected**（已连接） | IronClaw 与钉钉保持着 Stream 连接。 | 无需处理。 |
| **Reconnecting**（重连中） | 连接断开或一次尝试失败，IronClaw 会以递增的间隔重试，并显示最近一次的错误码。 | 稍等；如持续出现，请按下表查错误码。 |
| **Needs administrator**（需要管理员处理） | 重试无法解决问题，IronClaw 已停止重试，并显示原因码。 | 按下表排除原因，然后保存配置或重新激活扩展。 |

| 原因码 | 可能的原因 |
| --- | --- |
| `credentials_refused`、`connect_unauthorized` | 钉钉拒绝了 ClientID 或 ClientSecret。请重新复制两者，确认没有多余空格，并确认应用已发布。 |
| `handshake_unauthorized` | 钉钉拒绝了连接票据。请重新激活扩展以获取新票据；如反复出现，请检查凭证。 |
| `connect_unavailable` | 建连请求失败（网络问题或钉钉不可用）。请确认主机可以通过 HTTPS 访问 `api.dingtalk.com`。 |
| `connection_limit` | IronClaw 已达到流式连接数量上限，需要先移除其他流式扩展。 |
| `config_unavailable` | 部署配置缺失或不完整。请填全 DingTalk 卡片中的两个字段。 |
| 网络策略拒绝类的码 | 钉钉返回的网关主机不在扩展声明的主机列表内。主机名 `wss-open-connection.dingtalk.com` **尚未核实**，请把该码反馈给维护者，不要自行绕过。 |

卡片上还会提醒您：每组凭证只运行一个实例。

## 停止渠道

在 **Extensions** 页面移除 DingTalk 扩展。只有存在已安装的扩展时，IronClaw 才会保持与钉钉的连接，所以最后一位用户移除后连接会关闭，在重新安装之前不会再连接钉钉。重新安装后无需重启 IronClaw 即可重新连接。

重新安装后保留与不保留的内容：

- **保留：** 在 **Admin → Configuration** 中保存的 ClientID 和 ClientSecret，无需重新填写。
- **不保留：** 每位用户的配对。移除扩展会断开执行移除的用户的账号，该用户重新安装后需要再次配对。

## 配对账号（每位用户）

完成应用设置并不会把*您*连接到它。配对会把您的钉钉账号与 IronClaw 用户关联，从而避免同事冒用您的身份与智能体对话。

1. 在 Web 界面打开 DingTalk 扩展，选择 **Connect DingTalk** 生成验证码。
2. 在钉钉中与机器人**单聊**，把验证码作为完整的一条消息发送。配对只能在单聊中进行，不能在群里。
3. 机器人会回复钉钉已连接。

未配对者会看到：

- 在单聊中，发送验证码以外的消息，会收到请先连接的简短提示。
- 在群里，未配对成员 @机器人 会收到同样的提示，该提示**以单聊私信发给该成员**，不会发到群里。同一个群在短时间内最多发送一条这样的提示。
- 其他组织的成员不会收到任何回复。

## 使用机器人

- **单聊：** 直接给机器人发消息。
- **群聊：** @机器人。没有 @机器人 的群消息会被忽略。已配对的成员各自以自己的身份与智能体对话。
- 群里的消息被视为来自他人的不可信文本，而不是您的指令。
- 较长的回复会被拆成多条，每条最多 3000 个字符。

### 智能体主动发送的消息

当智能体发送您没有刚刚请求的消息（例如定时任务的结果）时，**只能发到您本人与机器人的单聊**，并且需要您已经完成配对并至少与机器人聊过一次。暂不支持向群主动发送，也不能让智能体替您给别人的单聊发消息。

## 常见问题

<AccordionGroup>
<Accordion title="卡片显示 Needs administrator 或 Reconnecting">
请对照上面的状态表和原因码表。最常见的原因是凭证错误，或者连接无法建立。
</Accordion>
<Accordion title="显示已连接，但机器人不回复">
确认切换为 Stream 模式后已重新发布应用、机器人能力已启用、您在应用的可用范围内。再确认您是否已配对：未配对的单聊会收到“请先连接”的回复；完全没有回复，则应检查连接状态或可用范围。
</Accordion>
<Accordion title="单聊正常，群里不行">
先把机器人加入该群，并在每条消息里 @机器人。其他组织的成员（例如跨组织群）会被忽略。
</Accordion>
<Accordion title="收到了消息，但回复没有发出">
发送需要应用已获得机器人发送消息的接口权限（具体名称以钉钉当前界面为准），且接收人要在应用的可用范围内，请在钉钉开放平台中检查。无法确认是否送达的回复不会自动重发，以免重复；请先查看钉钉聊天记录，缺失时再重新提问。
</Accordion>
<Accordion title="本组织的同事也被忽略">
只有机器人所属组织和发送者所属组织的标识都存在且相同，IronClaw 才会接受消息。如果本组织同事的消息全部被丢弃，可能是回调里没有 IronClaw 所期望的字段，请反馈给维护者，不要换用其他凭证重试。
</Accordion>
<Accordion title="两个实例在争抢消息">
停止多余的实例，或为它另建一个钉钉应用并使用独立的凭证。
</Accordion>
</AccordionGroup>

## 安全说明

- ClientID 和 ClientSecret 只保存在加密的密钥存储中，不会写入 `config.toml`、日志或卡片。
- **轮换凭证：** 在钉钉开放平台重置 ClientSecret，在 **Admin → Configuration** 中填入新值并保存，然后重新激活扩展。在此之前，连接会因凭证错误而失败。
- **已知的残留：** 钉钉为 Stream 连接返回的一次性连接票据位于连接地址中。IronClaw 自己持有的副本在使用后会被清零，但底层 HTTP 栈可能在内存中留下短暂的副本，IronClaw 无法清除。
- IronClaw 不使用钉钉回调里附带的单条会话回复 Webhook；回复通过 OpenAPI 发送，令牌由 IronClaw 自行换取。
